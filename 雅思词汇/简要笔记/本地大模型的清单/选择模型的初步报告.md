## 一、分析框架

### 1.1 核心使用场景：TRAE SOLO Agent 工作流

Agent 与普通问答不同，其工作模式是「思考-行动-观察」的多轮循环：

| 阶段 | Token 消耗特征 |
| :--- | :--- |
| 系统提示词 | 每次请求必带，固定消耗 |
| 任务描述 | 每次请求必带 |
| 代码库上下文 | 每次请求必带，**输入 Token 的大头** |
| 对话历史 | 逐步累积，越长越多 |
| 工具调用反馈 | 执行后返回完整结果，作为输入再次发送 |

### 1.2 关键筛选指标及权重

| 排名 | 指标 | 权重 | 说明 |
| :--- | :--- | :--- | :--- |
| 1 | **输入价格** | ⭐⭐⭐⭐⭐ | Agent 场景输入占比 80%+，是最核心的成本项 |
| 2 | **TPM 限制** | ⭐⭐⭐⭐ | 低于 40,000 会严重影响高频交互体验 |
| 3 | **MCP/工具调用** | ⭐⭐⭐⭐ | 决定 Agent 能否调用外部工具执行任务 |
| 4 | **上下文长度** | ⭐⭐⭐ | 至少 128K，保证能处理中型代码库 |
| 5 | **输出价格** | ⭐⭐ | Agent 输出较少，重要性偏低 |
| 6 | **视觉支持** | ⭐ | 可选需求，非必须 |

### 1.3 筛选门槛

| 指标 | 门槛值 | 依据 |
| :--- | :--- | :--- |
| 上下文 | ≥ 128K | 保证能承载中型代码库 |
| TPM | ≥ 40,000 | 保证 Agent 多轮对话不卡顿 |
| 工具调用 | 必须支持 | Agent 核心能力 |

## 三、筛选过程

### 3.1 第一步：TRAE SOLO Agent 场景的核心需求

根据 Agent 工作流分析，Agent 在任务执行过程中会：
- 反复读取代码库和对话历史
- 多次调用工具并接收反馈
- 需要快速响应，不能频繁被限流

因此：
- **输入 Token 消耗占绝对主导**
- **TPM 限制直接影响体验**

### 3.2 第二步：淘汰不符合基础门槛的模型

| 淘汰原因 | 模型 | 说明 |
| :--- | :--- | :--- |
| TPM 过低（< 40,000） | **Step-3.5-Flash** | TPM 仅 10,000，Agent 高频场景会严重卡顿 |
| 输入价格过高（> ¥2.00） | DeepSeek-V3.2、V4-Pro、GLM-5、Kimi 系列、MiniMax | 输入价格 ¥2.00-¥6.50，成本是 Qwen3.6-35B 的 5-16 倍 |
| 不支持工具调用 | DeepSeek-R1-0528-Qwen3-8B | 无法满足 Agent 核心需求 |

### 3.3 第三步：入围模型对比

| 模型 | 输入价格 | TPM | 工具调用 | MCP 能力 | 视觉 | 评分 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Qwen3.6-35B-A3B** | **¥0.40** | 40,000 | ✅ | MCP-Mark 37.0% | ✅ | 🥇 9.5/10 |
| Qwen3.6-27B | ¥0.60 | 40,000 | ✅ | 未明确 | ✅ | 🥈 7.5/10 |
| Qwen3-Coder-30B | ¥0.70 | 40,000 | ✅ | 专用函数调用 | ❌ | 🥉 8.5/10 |

**关键发现**：
- `Qwen3.6-35B-A3B` 的输入价格（¥0.40）比第二名（¥0.60）**便宜 33%**
- `Qwen3.6-35B-A3B` 是唯一同时具备**最低输入价格 + MCP 量化数据 + 视觉支持**的模型
- `Qwen3-Coder-30B` 输出价格更低（¥2.80 vs ¥3.20），适合输出较多的纯代码场景

### 3.4 第四步：免费模型对比

| 模型 | 上下文 | TPM | 工具调用 | MCP 能力 | 视觉 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **GLM-Z1-9B-0414** | 128K | 50,000 | ✅ | 官方支持 | ❌ |
| Qwen3.5-4B | 256K | 80,000 | ✅ | 未明确 | ✅ |

**结论**：`GLM-Z1-9B` 有明确的 MCP 官方支持，更适合作为免费主力。
